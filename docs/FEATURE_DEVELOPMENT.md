# Adding features to StudyCade

This is the branch's feature-extension guide. Follow [security boundaries](../SECURITY.md) and [architecture](ARCHITECTURE.md) before changing persistence or authentication.

## Current component boundaries

| Responsibility | Module |
| --- | --- |
| Navigation, selected deck, progress orchestration | `frontend/src/main.jsx` |
| File/paste preview and import workflow | `frontend/src/Importer.jsx` |
| Study deck editing and math input | `frontend/src/Editor.jsx` |
| Shared subject selector | `frontend/src/SubjectSelect.jsx` |
| Cloud account, restore, export, settings | `frontend/src/Settings.jsx` |
| Browser-only session convenience and download helpers | `frontend/src/browser.js` |
| Routed API calls | `frontend/src/api.js` |
| Guest workspace engine + IndexedDB | `frontend/src/guest.js` |
| Cloud workspace adapter, session generation, save queue | `frontend/src/cloud.js` |
| Practice/review pure helpers | `frontend/src/engine.js`, `exam.js`, `recall.js`, `study.js`, `reading.js` |
| Import parsing and backend trust boundaries | `backend/content.py`, `cloud_state.py`, `cloud.py`, `guest.py` |

Avoid adding another large feature inside `main.jsx`. Put UI in a focused component file, and pure calculations in a focused JavaScript module with adjacent `*.test.js` tests.

## Feature checklist

1. **Write the behavior contract first.** Specify input, output, error handling, existing workflows affected, and whether the feature stores study content or reads anything private.
2. **Trace current consumers.** Use the [Graphify graph](../graphify-out/graph.json) to find callers, but verify actual source; the graph indexes code only and is regenerated by CI.
3. **Keep import source intact.** Do not rewrite user-supplied notes, invent missing givens, or automatically forward coursework to an AI provider.
4. **Define both storage paths.** Guest uses browser IndexedDB; cloud uses an owner-scoped, version-aware remote workspace through the gateway. Do not silently transfer guest data at sign-in.
5. **Protect boundaries.** Treat API input, imported files, session metadata, and cloud state as untrusted. Client checks never replace server-side validation and RLS.
6. **Add tests before refactoring old logic.** Characterize edge cases, retries, invalid input, and storage isolation. Keep each change reviewable.
7. **Verify before review.** Run `cd frontend && pnpm test && pnpm build`, `python3 scripts/check_public_tree.py`, and `python3 -m unittest discover -s scripts -p 'test_*.py'`. Run the disposable backend smoke tests with the pinned `requirements-guest.lock` environment (see `docs/DEVELOPMENT.md`). Use disposable accounts for manual cloud checks.
8. **Keep releases separate.** Work in feature branches; do not push to `main` or the active deployment branch as part of development.

## Suggested module shape

For a new standalone study mode, prefer a component (e.g., `frontend/src/NewMode.jsx`) plus a pure engine module (`frontend/src/newMode.js`) and tests (`frontend/src/newMode.test.js`). Integrate only its navigation entry and required props into `main.jsx`. Reuse the existing API abstraction and session-aware persistence; do not create another independent storage system.

## Review priorities

First confirm guest/cloud parity, error states, data-size limits, keyboard/accessibility behavior, progress preservation, and interaction with current imports and exports. The optimizer should reduce duplicate **behavior**, not remove intentional trust boundaries or collapse unrelated modules to minimize line count.
